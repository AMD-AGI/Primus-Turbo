初版计划写于今天上午。**它的四个主要候选里三个已被当天的实测打死**，

## 一、已经作废的（连同作废它们的证据）

| 初版主张 | 状态 | 证据 |
|---|---|---|
| 前向 `n_block` 64→128→256，「LDS 一字节不涨」 | **死** | LDS 那半是对的，但 VGPR 涨。128 慢 **3.2×**，256 慢 **9.9×** |
| `BLOCK_M` 256→128 提高 WG 数 | **死** | 慢 **25%**。五个点把 tile 一族围死，出货点是局部最优 |
| 接上 warp specialization（4 波） | **路障** | V1 loader 在 flydsl 0.3.2 下编译失败，V2/V3 硬要求 8 波。aiter 那份走不通 |
| 后向 S2-c：4-wave + `BLOCK_KV=128` | **死** | `BLOCK_KV=64` 已经要 ~1110–1124 VGPR 撞 1024 天花板 → 溢出，**而溢出的 build 在这张卡上会挂** |
| 后向 S2-a：放宽确定性门以换原子 dq | **无收益** | `k_dq` 已是 960/1024 VGPR、1 wave/SIMD —— **已经站在 bar 的配置上**，寄存器轴算术封死 |
| S0-c：用 `SQ_WAIT_*` 区分 stall / starvation | **不可能** | 这张卡**不提供任何** wait/stall 计数器 |
| S0-d：用 `SQ_VALU_WMMA_FLOP_BF16` 实测发射 FLOP | **不可能** | 该计数器**静默返回 0**（在明确发射数百万条 WMMA 的 bar 上读到 0） |
| 「LDS 空洞挡掉一半占用率」（我上午的头条） | **死** | rocprofv3 的 VGPR 列是 ISA 值的一半。真实 740，**VGPR 本身就定死 1 wave/SIMD**，空洞零成本 |

**共同的失败模式**：一个真实观察，往前多推了一步，然后被当成观察本身引用。
今天六次里有五次是这样。

## 二、站得住的（今天实测，两边都有对照）

| | wave/WG | 驻留 | LDS | ISA VGPR | VGPR/SIMD | 实测 |
|---|--:|--:|--:|--:|--:|--:|
| `k_dkdv`（后向 66.7% 时间） | 1 | 1/SIMD | 70656 | **740** | 740/1024 | — |
| `k_dq`（后向 32.6%） | 1 | 1/SIMD | 8704 | **960** | 960/1024 | — |
| FlyDSL 前向 | 8 | 2/SIMD | 327680 | **~448** | 896/1024 | 2.356 ms · 947.8 TF/s |
| **ASM bar 前向** | 4 | 1/SIMD | 327680 | **1024** | 1024/1024 | **1.557 ms · 1434.0 TF/s** |

- 前向差距 **1.513×**（今天 101 次交错实测，此前只是 spec 里的一句话）
- 四个 kernel 全部 `Scratch_Size = 0`，都没溢出
- icache 彻底无关：bar 自己的 miss 率 0.0148%，比我们高两个数量级，仍快 1.4×
- 环境：hipBLASLt 可用（`HIPBLASLT_TENSILE_LIBPATH` 指向宿主完整库），profiling 不挂卡

**唯一没被证伪的结构差异**：bar 的填充路径**零 `buffer_load`，全 TDM**；
我们 `k_dkdv` 热体每迭代 **36 条 `buffer_load`**（32 b128 + 4 b32），`k_dq` 32 条 b128。

## 三、后续轮次

### 后向 · round 13（**进行中**）：TDM 2D

封死它的记录不成立：那是 **gfx950** 上 `buffer_load ... lds`（**另一条指令**）的 A/B，
归因于 **+16 `s_barrier`** 和 **−32 AGPR**，而 gfx1250 **没有 AGPR**、
我们的 WG 是**单 wave** 且 `s_barrier` 本来就是 **0** —— 两条归因在这里都不可能发生。
flydsl 0.3.2 的 TDM 2D 面完整，其 padding 模式恰好复现我们 g16 调出来的 `X_ROW_B = 272 B`。

**预期符号：未知。** 写成这一轮的证伪目标，不写成预测。
先例两边都有：删流量在 `k_dkdv` 上付过 +11.0%（g09），同样的删在 `k_dq` 上一分没有（g12）。

### 后向 · round 14+（按 13 的结果分叉）

- 若 TDM 为正 → 推到 `k_dq` 的 32 条 b128，再考虑 TDM 让出的 ~128 个 VGPR 能买什么
- 若 TDM 为负或 NULL → 后向的机制清单就**空了**。届时诚实的动作是**宣布后向到顶**
  （499.1 TF/s，0.70× of aiter），把卡时全部转给前向，而不是再开十轮去撞已知的墙

### 前向 · 主线

aiter 那份的**参数面已经被我扫完了**，只剩两件事：

1. **`O_VARIANT` v3 → v1，实测 +1.90%**（101 次，两会话一致，描述符独立确认是两个不同 kernel）。
   这是现成的、零风险的提升，应当带进前向作业的 baseline。
2. **4 波 + 全 TDM 填充必须在我们自己的 kernel 里写**，不是在 aiter 那份上调参数。
   bar 已经证明这个形制能到 1434 TF/s。

脚手架（vendored baseline + job spec，各带对抗验证）正在 CPU 上搭。
**⚠ 单卡：前向作业与后向作业不能同时跑。** setup 要约 58 分钟卡时（实测 618 s + 2850 s）。

另有一个**后向两次为正、前向零接触**的杠杆：4096 个 WG 只有 1 WG/CU 驻留、要跑 16 批，
causal 下每 WG 工作量正比于 q 序号，尾巴很贵。后向 round 12 靠纯派发顺序拿过 +4.91%。

### 每轮固定动作

- `--pmc`，**只用白名单里那九个**计数器，约 2 分钟。价值不在计数器本身，
  而在每趟白拿的 kernel 描述符 —— `Scratch_Size != 0` 是最便宜的溢出检查，
  而**溢出的 build 在这张卡上会挂**。
- 轮次结束 **push**。
- 建候选前按**机制** grep 语料库，并检查该证据是 gfx1250 还是 gfx950。

## 四、绝对不要再做的

- **不要**引用任何绝对天花板。1002.7 TF/s 是一条 Triton GEMM 的成绩，而 bar 实测 1434 —— 高 1.43×。真峰值至今未钉死，且在这张卡上**没有计数器能钉死它**。
- **不要**从 rocprofv3 的 VGPR 列推占用率台阶。先乘 2。
- **不要**用那六个静默归零的计数器，**也不要把它们的 0 当成发现**。
- **不要** `resume --config`（bump spec → 重建 `op/` → 毁掉 refcache 补丁）。
- **不要**在轮次启动或运行期间手改 `op/current/` —— 它每轮开始都会从冠军存档恢复，
  而 `op/baseline/` 不会，于是同一个补丁只落到一边，**制造出臂间环境差异**。
- **不要**把 `op/core`（385 MB）和 `op/core.gpu` 复制进任何新作业。
