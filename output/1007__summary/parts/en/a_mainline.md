## (a) Before optimization: what goes wrong when running the main branch as-is

Scope: the start-up phase, 2026-09-10..09-14. In this section "main" means the head of upstream main at the time, `c1325c7e` (#481, 2026-09-09, the first time a Triton dense attention backend was added for gfx1250). The first working branch, `gfx1250-attn-dispatch-and-tuning`, was branched off it (`git merge-base f8c45dee origin/main` = `c1325c7e`). The "current state" column in the tables has been checked against the local `origin/main` = `8cda13c7` (09-30). The target op is Llama-3.1-8B attention: b4 s8192 hq32 hkv8 d128 bf16 causal (bottom-right), BSHD, GQA G=4.

Notation and conventions:
- **A0-VR**: A0 (`heliosr-1b114-c07-1`) in its VR-throttled state before the 09-29 firmware reflash; sclk capped at 1100 MHz, ~0.97-1.07 GHz under load. **A0-RF**: after the 09-29 firmware reflash; ~1.74-2.03 GHz at op level, ~1.5 GHz during training. **B0**: `ctheliosp-1b112-a37-1`, 2133-2244 MHz under load. Absolute numbers from the three states are not comparable with one another, and the various "ratios" cannot stand in for one another either: ① Cross-machine A0-VR→B0: 5 like-for-like rows of the same Triton-family code give 1.88-2.01x (median 1.93x; all 7 rows of FINAL-TABLE give 1.88-2.12x, median 1.97x). This is a ratio between two cards, and B0's own dmesg also shows VR throttle warnings (the 0914 repro estimates their cost at ~9%), so it is not A0's own throttle cost (0914__repro__c07/RESULTS.md:32-38, 124-130). ② For ASM attention, also across machines, only the fwd ratio of 1.118x holds (A0-VR 09-15 1.572 ms vs B0 09-14 quiet window 1.406 ms, both ASM fwd on the tune ruler). The claim in 0915__opt/JIRA-TRACE-ANALYSIS.md:148-156 that "attention differs by only 1.12-1.15x across machines" (bwd 1.150x; total 11.726 vs 10.236 ms, 1.146x) does not hold: the bwd item compares A0's shim artifact at 10.160 ms (retracted 09-24) with B0's fused Triton bwd at 8.835 ms (on 09-14 B0 had no ASM bwd yet; `--impl asm` meant ASM forward + fused backward), which are not the same kernel. With fused Triton bwd on both sides, bwd is 17.735/8.835 ≈ 2.01x and the total is 19.285/10.235 = 1.88x (0915__repro__c07/RESULTS.md:17; 0914__campaign/RESULTS.md:102-103; 0914__campaign/HANDOFF.md:246; (d) d.3). ③ A0 itself, before→after the firmware reflash: 1.24-1.67x at op level with the same code and the same method (mean of the two orders). The e2e 1.44x is not a clean same-method comparison and is not purely a platform difference: the before value comes from the voided 09-28 run, a process in which the FlyDSL fwd tree repointed `HIPBLASLT_TENSILE_LIBPATH` to the host library midway; between the two runs the driver and the e2e suite both changed as well. It serves only as a reference (see the notes after the a.1 table).
- FLOP convention: fwd 2.199292e12, bwd 5.498229e12, fwd+bwd 7.697e12 / call. The documents of the time reported only the fwd+bwd total, and that total is exactly the sum of the two. The "per-direction TF/s (converted)" column in the tables was computed in this section with the current convention.
- Rulers: **tune** = `tools/gfx1250/tune_attention.py` (median of CUDA events, 20 iters / 5 warmup, 256 MiB L2 flush per rep, SQNR against an fp32 reference computed separately for each of the four tensors out/dq/dk/dv). **bench0910** = the 09-10 log of the Primus-side attention bench (`Primus:output/0910__fa_opt/attn_bench_gfx1250.log`). **E2** = `E2_bench.py` from op-evolve phase-1 (warmup 5, iters 20, repeated 3 times). **bat** = `benchmark/ops/training/bench_attention_turbo.py` (09-30).
- Source paths: relative paths without a prefix are all under `Primus-Turbo/output/`. `0913/` = `0913__opt_plan__claude/`; `ph1/` = `op-evolve:output/0911__fa_gfx1250_phase1/` (op-evolve = `/home/lihuzhan/code/2026_0910__op-evolve/op-evolve/`); `Primus:` = `/home/lihuzhan/code/2026_0828__primus/Primus/`; `wt-llama31 README` = `wt-llama31/docs/gfx1250_llama31_8b_e2e/README.md` (the 10-05 tutorial).

**Summary.** Before optimization, running Llama-3.1-8B attention with main on gfx1250 had three layers of problems:
1. By default it does not run at all. Under torch 2.11 it crashes on import; the default dispatch lands on CK, which supports only CDNA; all tests are skipped, so there is no signal whatsoever.
2. The only backend that can be pinned by hand, Triton, uses a single config copied verbatim from CDNA and is ~1.9x slower than the incumbent flex, with dkdv accounting for 61.5%.
3. e2e cannot detect any attention change. First, the image's BLAS was broken or extremely slow (rocBLAS 27.4 TF/s; later traced to a path mismatch, plus the missing tuned library for the NN layout). Second, `converters: []` meant that what ran in e2e was always flex. Third, Primus's turbo default config switches on FP8/MX linear as well; in the 09-14 "turbo vs flex 1.459x", both arms were flex, and the real source of the difference is still unresolved.

In addition, all numbers on A0 were taken under the VR throttle (1100 MHz), and from 09-04..09-13 this card wedged on average about once every two days (5 times in total). So every absolute number in this section must carry a machine and clock label, and for cross-machine and cross-clock ratios it must also be made clear which kind they are (see "Notation and conventions").
