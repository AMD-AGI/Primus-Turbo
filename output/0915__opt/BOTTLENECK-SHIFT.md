# 修完 GEMM 之后，瓶颈换了人

第一次 profile 产生 6.21× 的那个配置（此前只 profile 过修 GEMM 前和只修一半的版本）。

配置 `repro_l8b_turbo_conv_8L_prof.yaml` + nkfix v3，落在 38,000–40,000 tps 的模态，
命中统计 `{'dgrad': 570, 'wgrad': 570, 'wgrad_skipped_oom': 0}`。

## 单步构成的三次演变

| | 修 GEMM 前 | 只修 dgrad | **dgrad+wgrad 都修** |
|---|--:|--:|--:|
| 单步 GPU kernel | 5189 ms | 2835 ms | **794 ms** |
| GEMM | 94% | 85.9% | **38.6%** |
| attention | 3.3% | 6.0% | **20.8%** |
| 其余 | 2.7% | 8.1% | **40.6%** |

**坏 tile 已经完全消失**：GEMM 里 99.9% 是 `MT256x256x128`（n=171），
此前占 89.8% 的 `MT32x16x32` 一个都没有了。

## 两件事因此变了

### 1. attention 从 3.3% 变成 20.8%，它现在值得优化了

"ASM 反向默认关闭"这个决定，是在 attention 只占 3.3%、端到端差异 −0.28%（0.15× sem）时做的。
**那个前提已经不成立。** 算子级 ASM 反向比融合反向快 1.74×（10.160 vs 17.686 ms/层），
8 层每步省约 60 ms，对现在 794 ms 的单步是 **7.6%** —— 远高于当时测不出的量级。

同理，Triton 两 kernel 路径的 sweep 也从"不值得"变成"值得"。

### 2. 最大的一项现在是"其余"，而其中一半是 nkfix 自己的拷贝

`elementwise_kernel_manual_unroll<128, 8, ...>` 占 **182.87 ms**，
是"其余"的 57%、整个单步的 **23%**。

修 GEMM 前同一个 kernel 是 **86.59 ms**。**翻了一倍，多出来的约 96 ms 就是 nkfix 的转置拷贝** ——
dgrad 每次拷 B，wgrad 每次拷 A 和 B。

这笔账整体仍然大赚（GEMM 2434 → 306 ms，省 2128 ms，拷贝只花 96 ms），
但它现在是**第二大可优化项**：

- **dgrad 的 B 是权重**，一步之内不变，理论上每层每步只需转置一次而不是每次调用都转。
  （0915 写过一个缓存变体，但它只有 dgrad 规则且增加常驻显存，已删除 ——
  见 `bin/README-nkfix.md`。要重做的话应当基于 v3 的两条规则，并且用瞬时而非常驻。）
- **wgrad 的 A 是 dout**，每次都不同，无法缓存。

## 下一步的优先级（按现在的占比重排）

| 项 | 占单步 | 可能收益 | 成本 |
|---|--:|---|---|
| 其余（含 182.87 ms 拷贝） | 40.6% | 缓存 dgrad 的权重转置，上限约 96 ms 的一部分 | 中 |
| GEMM | 38.6% | 已在好 tile 上，剩余空间未知 | — |
| **attention** | **20.8%** | ASM 反向约 60 ms（7.6%）；Triton sweep 未知 | **低** |

**attention 是现在最便宜的一项** —— 优化已经做好躺在那里，只差一个环境变量，
而且资格门、正确性验证都齐了。正在重测它的端到端价值。
